# v1.9.1 — unified session inventory, separate usage scopes

## What changes

The v1.9.0 terminal emitted local summary, every local detail table, then a
separate Cloud lifetime table. v1.9.1 renders one inventory first. Details follow
that same order. It changes presentation, not how Cloud usage is collected.

| Column | Meaning |
| --- | --- |
| PROJECT / SESSION | Independent identity columns; explicit backend project name or cwd leaf when supplied. Never infer a project from a task title. |
| SRC | LOCAL, CLOUD, or BOTH; telemetry origin, not machine/executor location. |
| PERIOD≈ | Selected local window's weekly-equivalent estimate. Cloud-only rows have no period amount. |
| LIFE % | Backend Cloud lifetime weekly-allowance-relative amount. It is not current-week consumption. Local-only rows have no lifetime amount. |
| MODEL(S) / TIER(S) | Local models/tiers when local data exists; Cloud-only models only from explicit backend group IDs. Missing metadata stays unknown. |
| 1H≈ / CREDITS* | Local recent-hour estimate and local reference credits. Cloud balance credits are separate diagnostics, never substitutes. |
| STATE/DATA | Local activity/health, or backend Cloud availability; `available` does not mean running. A BOTH row shows local activity and a Cloud availability continuation. |

At 144 cells, project and session receive 18 and 34 cells. `--wide` retains
local token/cache/share diagnostics and Cloud lifetime 5h/balance values on
continuations. Narrow layouts retain identity, source, and both weekly columns,
moving model/tier/credit diagnostics below the row. Color respects existing
`--color` / NO_COLOR policy. Remote metadata is sanitized at the terminal boundary;
JSON/CSV retain the raw data as before.

## Identity versus measurement

Only an exact root thread ID joins the two views. A BOTH entry has one title and
one detail section, but still two independent measurements. A Cloud child
whose local tokens were rolled into another visible root remains an individual
Cloud lifetime entry, with a note about the local rollup. It is not folded into
its parent's Cloud amount. Same names/projects are not evidence of identity.

The combined inventory sorts by project/name and stable ID, missing-data-only
entries last. It does not rank a Cloud lifetime amount against a local 12h
amount. A known zero is data, not unavailable. `partial` and `unavailable` stay
visible and do not become zeros. Cloud model/effort/speed groups are not used to
invent timestamped local token usage.

Only LOCAL TOTAL is shown; it is exactly the selected local data's subtotal.
No Cloud lifetime total or combined period total is fabricated. A Cloud amount
can include Mac execution and lifetime usage may predate the selected window or
span multiple quota resets. A backend lifetime percentage may exceed 100%.

## Details and commands

```
codex-usage 12h --cloud --details
codex-usage 24h --cloud --wide
codex-usage cloud --details
codex-usage 12h --cloud --cloud-thread THREAD_ID --json
```

The full inventory precedes all detail tables. Local details keep the existing
token/model/tier/component/agent breakdowns. Shared roots include a distinctly
labeled Cloud lifetime block. Cloud-only details contain backend weekly/5h,
balance, availability, freshness and explicit models if supplied, not empty
local token tables. The backend report-wide freshness remains the oldest batch
time (or unavailable); it is not a per-session activity timestamp.

`--cloud` stays opt-in. Normal local commands remain offline with the prior
layout. Cloud requests use exactly the v1.9.0 inventory/usage interfaces and
read-only credential behavior, without additional requests, login refreshes,
thread start/resume actions, or writes to quota calibration.

## Export and cache compatibility

Combined JSON preserves the local `sessions` array and `cloud_usage` object,
adding `unified_sessions` and `unified_session_order`. Each joined record has
`local_usage` and `cloud_usage` objects (or null), explicit scopes and sources;
there is no numeric addition. Cloud-only JSON keeps its v1.9.0 shape.

Combined CSV retains separate measurement rows, adjacent for matching IDs.
`host`, `scope`, backend percentages and balance credits remain distinct from
local estimate columns. Cloud `project_name` and `cwd` columns are additive.
Original field ordering and raw per-source values are retained.

Cache schema, rate cards, Fast assumptions, quota policy and all arithmetic are
unchanged. There is no transcript re-index or quota cache migration. Existing
uncertainty from missing tiers, stale snapshots or local-only quota calibration
is not resolved by unifying presentation.

## Verification

Tests cover mixed-source, both empty and one empty, same ID versus same title,
Cloud child/local rollup, zeros and missing/partial data, scope-specific totals,
model/tier separator handling, deterministic ordering, CJK widths at 80–144
cells, full-screen capping, colors and remote control characters, details before/
after summary, additive JSON/CSV, and CLI calls with mocked Cloud transport.
Fixtures are synthetic; no credentials, private messages or real backend lifetime
results are committed or used to infer undocumented pricing behavior.
