# v1.5.2 calibration rebase

`codex-usage` v1.5.2 keeps weekly-attribution calibration in the same credit coordinate system as the currently displayed `CREDITS*`.

When the embedded token rate card changes, historical quota observations still contain useful backend anchors (`used_percent`, snapshot timestamp, weekly reset/window), but their stored `local_credits` were computed under the old rate card. v1.5.2 therefore does not reuse those old credit totals directly.

For the current weekly reset epoch, the tool tries prior anchors newest-first. For each anchor it reconstructs local token usage from the weekly-window start through the anchor timestamp and prices that token history with the current rate card. A fully priced replay is stored as a current-revision quota observation with source `rebased`, producing a `LOW · rebased baseline` until current-rate delta observations mature.

If an anchor interval contains an unpriced model such as GPT-5.3-Codex-Spark, that anchor is skipped. If no prior anchor can be completely repriced, calibration remains `LEARNING`; the tool will not mix old-rate credits-per-percent with current-rate `CREDITS*`.

This rebase changes only quota calibration. Session lineage, token-delta accounting, the incremental rollout index, and the v1.5.1 partial/lower-bound behavior remain unchanged.
