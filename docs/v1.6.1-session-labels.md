# v1.6.1 project-aware session labels

`codex-usage` v1.6.1 builds the visible `SESSION` label from Codex's structured local thread metadata instead of relying only on the generated first-prompt title.

## Label priority

1. Explicit Codex thread name (`threads.name`), when set.
2. Codex preview/title/first user message as the descriptive fallback.
3. A context prefix, chosen from the assigned Codex project, the cwd directory, or the git remote repository name.
4. The short session ID only when no descriptive metadata exists.

Typical labels are therefore:

```text
[steerRL] Sparse-1 S3 comparison
[knowing-to-see] Read AGENTS.md and continue the current stage
```

When two visible rows still have the exact same resolved label, a stable marker derived from the session ID is inserted immediately after the project prefix so it remains visible even in a narrow terminal column.

## State database compatibility

Current Codex databases may expose `threads.name`, `threads.project_id`, `projects`, and `project_roots`. The reader discovers columns and tables dynamically, so older `state_5.sqlite` schemas continue to work. On an older schema, cwd/repository context is used instead.

This feature changes only display metadata. It does not change token attribution, credits, weekly calibration, or the persistent token-event cache schema.
