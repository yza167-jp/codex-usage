# v1.5.5 weekly-first usage model

`WEEKLY≈` is the primary local usage unit in v1.5.5. It expresses selected local usage as a share of one plan weekly allowance, while the header's `CURRENT WEEK` remains the latest backend-reported meter for the active quota epoch.

Calibration priority:

1. clean current-rate snapshot intervals;
2. current/historical current-rate baselines, including safely rebased historical backend anchors;
3. a clearly labeled low-confidence plan bootstrap (`SEED`) so weekly-equivalent attribution remains available immediately after a reset or on a fresh cache.

Unpriced models such as GPT-5.3-Codex-Spark make only their containing interval/session partial. Those intervals are excluded from calibration and report attribution uses `≥` lower-bound semantics. A dirty interval does not invalidate later clean intervals in the same week.

The default summary and detail tables place `WEEKLY≈` before `CREDITS*`; `1H≈` is the trailing-60-minute weekly-equivalent burn. Credits and cache-tax remain secondary diagnostics.
