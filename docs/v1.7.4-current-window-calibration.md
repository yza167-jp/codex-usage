# v1.7.4 — current-window quota calibration

## What was wrong

v1.7.3 selected complete intervals across all reset periods. Any surviving old
delta prevented a current baseline from being considered. Known models with
Unknown service tiers made new intervals incomplete, so an old 264.253
credits/percentage-point conversion could persist while the current backend
snapshot was 62% and the local estimate was 128.6%. The old plateau anchoring
also generated overlapping copies of the same percentage movement.

## New estimation policy

Reference prices, Standard/Fast accounting, parent/subagent token accounting,
plan seed constants and token-cache schema 3 are unchanged. This is a calibration
policy correction, not a new official weekly rate or a token-deduplication audit.

1. Rebuild **current snapshot/reset-period** intervals from stored raw quota
   snapshots and existing cached token deltas. Match account, plan, mode, pool,
   reset, window duration and as-of timestamp. No transcript rescan is needed.
2. Close an interval at the first snapshot at least **3 percentage points** above
   its anchor. The endpoint becomes the next anchor. Count tokens in `(start,
   end]`. Repeated queries while the displayed percentage stays flat contribute
   no additional independent blocks or percentage points. Small final movements
   remain pending; more queries are not more independent evidence.
3. A decrease under the same reset ID restarts the evidence segment. It disables
   whole-week reconciliation, since the earlier usage no longer matches that
   denominator. No block ends at 100% or crosses the reset boundary.
4. Complete model/tier records can teach `current_delta`. Known models whose
   tiers are Unknown can teach `current_delta_assumed` on the **same credit
   assumptions as the report** (Standard by default; `--fast` applies only to
   Unknown). Assumption-dependent estimates always remain LOW. This is an
   empirical scale for the observed workload mix, not a verified provider rate.
5. Unpriced models, Flex, unsupported tiers/providers, malformed history or an
   unresolved parent exclude that interval. Later intervals can learn normally.
   Store reason counts rather than promoting legacy `complete=0` rows blindly.
6. Use the aggregate credits / aggregate percentage movement of eligible blocks
   in the past 48h of this period. With at least five blocks, reject extreme
   ratio outliers before aggregation. For complete evidence, MEDIUM requires
   three blocks / 10pp, HIGH six blocks / 20pp, with max/min ratio <=1.5.
   These labels describe sample consistency, not statistical confidence bounds.
7. With insufficient current blocks but at least 3% usage below saturation and
   eligible local history, an explicitly labeled `current_baseline[_assumed]`
   divides current local credits by the backend percentage. This **assumes this
   machine explains the account's usage**; agreement is true by construction.
8. Otherwise use a dated same-policy historical cohort, then compatible legacy
   complete evidence, both at LOW and no older than 14 days. Legacy overlapping
   intervals are discarded. Never combine epochs into one historical cohort.
   Last resort remains the visibly unvalidated plan SEED. Model-specific pools
   are not used to calibrate all local sessions.

The 3pp threshold, 48h/14-day ages, confidence thresholds and outlier policy are
**tool heuristics**, not OpenAI usage limits. Another device, cloud tasks,
provider lag, workload changes or incomplete local records can bias the scale.
Unknown tier fitting cannot determine whether a specific request was actually
Fast. No model price or undocumented Astra allowance multiplier was changed.

## Conflict handling, not clipping

Compare local-current-period credits and the backend percentage **at the same
snapshot timestamp**. If the estimate exceeds the backend by more than
`max(3pp, 25% of backend used%)`, emit `CALIBRATION MISMATCH` with the conflicting
numbers. This is a one-sided plausibility check, not a proof of external usage.

When history is eligible and unsaturated, a conflicting slope may fall back to
an explicitly labeled `reconciled_baseline`; the rejected slope and warning are
retained. It is a local-only allocation, not independent evidence or validation
of the token counters. With unpriceable/incomplete history no such normalization
is allowed: keep the provisional estimate with a CONFLICT warning. Percentages
are **never clipped to 62% or 100%**. Selected ranges can span resets or future
activity relative to a stale snapshot; their weekly-equivalent sum can exceed
100% legitimately. Stale/expired snapshots are called out separately.

## Display and export semantics

PROJECT/SESSION separation, model price ordering, full model continuation lines
and the 144-cell layout remain. The scale line identifies current-window blocks,
assumed tiers or dated historical priors. `--details` includes evidence dates;
JSON exposes provenance, excluded counts, assumptions and warnings.

`WEEKLY≈` is **never a guaranteed provider-quota lower bound**. Partial rows use
`12.3%?`, not `≥12.3%`. Reference credits retain their existing `+` marker. Existing
JSON/CSV `weekly_estimate_is_lower_bound` fields are retained but always false;
new `weekly_estimate_is_partial` fields carry incompleteness. All percentages in
session/TOTAL/1H, model/tier/component/agent details and exports use the same
selected scale. CSV appends calibration metadata without moving existing fields.
`local_coverage_percent` is null: fitting a scalar is not a device-coverage audit.

## Safe migration

Do **not** delete the cache or reset quota history. Raw `quota_snapshots`, legacy
`quota_observations` and `quota_intervals` remain. Add a pool column to snapshots
and a separate derived `quota_intervals_v2` table. Its key includes calibration
policy revision and the existing rate-card coordinate. Rebuild only derived
current-period rows on each query using prefix-summed cached deltas; repeated
queries are idempotent. Schema-3 token events/files are not invalidated.

## Validation and limits

Tests reproduce the audit-shaped stale-prior failure using synthetic receipts,
including the two old complete records and repeated current percentage plateaus.
They also cover half-open boundaries, Unknown vs unpriced/Flex/provider/history,
reset/decrease/saturation, future and stale snapshots, identity/pool/mode isolation,
cache preservation, mismatch versus explicit reconciliation, JSON/CSV/rendering
consistency and a repeat CLI query with zero token-index rereads.

These are controlled tests, **not a replay of the user's raw local transcripts**.
The release cannot certify the absolute token totals on a machine it has not
inspected. It fixes the confirmed stale/overlapping calibration logic without
concealing independent accounting problems behind an unlabeled normalization.
