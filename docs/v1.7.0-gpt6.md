# v1.7.0 — GPT-6 Astra accounting

## Reference rates and scope

Verified on **2026-09-05**. The public ChatGPT **Work/Codex** reference rate for
GPT-6 Astra is **250 / 25 / 1,250 credits per million uncached input / cached
input / output tokens**. Work/Codex Fast is **2.5×** Standard, giving
**625 / 62.5 / 3,125**. This is a local credit-equivalent reconstruction, not an
OpenAI invoice or a published conversion from credits to subscription limits.

Sources:

- [OpenAI Work/Codex credit rate card](https://help.openai.com/en/articles/11481834-chatgpt-rate-card)
  — GPT-6 Astra row and explicit 2.5× Work/Codex Fast note.
- [OpenAI Work/Codex token-based rate card](https://help.openai.com/en/articles/20001415-chatgpt-rate-card-enterprise-token-based-pricing)
  — distinguishes Work/Codex pricing and the GPT-6 Astra Codex long-context exception.
- [GPT-6 Astra API model page](https://developers.openai.com/api/docs/models/gpt-6-astra)
  — canonical model identifier. **API billing is not the Codex subscription meter.**
- [Codex model identification](https://github.com/openai/codex/blob/459a79eb85400af759e9220c7bafb4429ae07516/codex-rs/tui/src/daybreak.rs)
  — recognizes Astra and a separate `gpt-6-astra-wm` identifier in the client.

The standalone Codex rate-card page and other older documentation snapshots may
lag the new model's rollout. This release uses the explicit Astra Work/Codex row
above as its reference for local estimates, including Plus/Pro estimates. It
does not assert that the rate card publishes Plus/Pro weekly token weights.

This is **an additive model-support release**, not a repricing of all history.
Existing model rates are pinned to v1.6.2. In particular, current purchased-credit
promotions must not silently change the coordinate system used to estimate
included weekly allowances. The header therefore shows both the original
rate-card date and the date of the GPT-6 addition. A future general repricing
requires a separate calibration revision and replay.

## Identifiers

`gpt-6-astra` displays as **6 Astra**. The exact shorthands `gpt-6` and `gpt6`
are accepted as **tool compatibility aliases** for Astra, not as a claim that
these are official API model IDs. A narrowly matched
`gpt-6-astra-YYYY-MM-DD` identifier uses the Astra family reference rate.
Case normalization, whitespace stripping, and the existing `openai.` prefix
handling continue to work. Alias matching also applies when reading existing
cached model IDs, not just freshly scanned transcripts.

There is intentionally **no `gpt-6*` wildcard**. Pro, mini, preview, and other
unverified variants do not inherit the Astra rate. The client's
`gpt-6-astra-wm` can be labeled **6 Astra WM**, but remains unpriced until its
pricing is verified: an access-family mapping alone is not billing evidence.
Unrecognized identifiers retain their token counts and the existing partial
estimate treatment instead of disappearing.

## Accounting

For input counter `I`, cached input `C` and output `O`, the Standard estimate is:

```text
cached = min(I, C)
uncached = max(0, I - cached)
credits = (uncached * 250 + cached * 25 + O * 1250) / 1,000,000
```

Reasoning output is already part of output; it is not added again. The existing
service-tier state machine applies the multiplier independently to each token
delta, so toggling Fast does not retroactively change prior Standard usage.
Unknown tiers retain their uncertainty flag. `--fast` only changes Unknown
segments to a Fast assumption; it does not override detected Standard segments.
Flex remains incomplete because this release does not establish a Codex Flex
subscription rate.

Do not import the API's Astra Fast multiplier, cache-write charges or long-context
surcharges into this Codex estimator. The cited Codex documentation explicitly
exempts Astra from the additional >272K long-context multiplier and does not
charge cache writes.

Every consumer of the shared rate map benefits: session summaries, TOTAL,
trailing-hour usage, usage components, model/tier tables, parent/child agent
attribution, JSON and CSV. Weekly percentages continue to use local calibration
or the visibly labeled `SEED` fallback. A new model being priceable does **not**
make a low-confidence weekly scale authoritative.

## Cache and calibration compatibility

The token cache stays at schema **3**. Previously unpriced Astra token events
are already stored and are priced when queried; no manual rebuild is needed.
The complete historical calibration key stays at
`2026-08-12-r3-tier-aware`: **none of the formerly priced models or tiers changed
rate**, so complete historical samples remain in the same coordinate system.
Incomplete old intervals are still excluded and are never silently promoted to
complete. New/recomputed complete Astra intervals can contribute normally.
Quota history, plan bootstrap seeds, the 144-cell report cap and project-aware
SESSION fitting are preserved.

## Validation

Synthetic regressions cover model IDs and nonmatching variants; Standard/Fast
and Unknown behavior; cached input and reasoning treatment; no API-only
surcharges; mid-session tier changes; mixed GPT-6/GPT-5.6 parent/subagent rollup;
TOTAL, 1H, weekly and export values; pricing pre-existing cached GPT-6 events
with zero transcript rereads; calibration-history compatibility; and a fresh
weekly reset using `SEED`. No real user transcript or authentication data is
included in these tests.
