# v1.6.0 Fast-aware accounting notes

`codex-usage` v1.6.0 treats service tier as time-varying rollout state rather than a session-wide flag.

## Persisted signals

The parser recognizes tier settings from `turn_context`, `thread_settings_applied`, and compatible event payloads. Values are normalized as follows:

- `priority` or `fast` → Fast
- `default`, explicit null, or an omitted tier in a full `thread_settings_applied` snapshot → Standard
- `flex` → Flex
- no usable persisted marker → Unknown

Each cumulative `token_count` snapshot is associated with the most recently applied model and tier. Counter deltas are therefore priced per model–tier segment, allowing one session to contain both Standard and Fast usage.

## Estimation policy

Detected Fast segments receive the published Fast multiplier. Detected Standard segments always retain Standard pricing. Unknown segments default to Standard-priced lower bounds; `--fast` changes only those Unknown segments to a Fast assumption. Flex and models without an embedded applicable rate remain explicitly partial.

The terminal, JSON, and CSV outputs expose tier metadata, while `+` and `≥` continue to mark incomplete credit and weekly-equivalent estimates.

## Cache and calibration

Cache schema v3 stores service tier per event and the current tier parser state per rollout. Upgrading causes a one-time automatic re-index of rollout token events; quota observation history is retained. Weekly calibration uses a new tier-aware revision, and compatible historical backend anchors can be replayed using the current rate card and tier logic.
